# 实验指导：高频时间维度因子的商品期货时序 CTA 复现

面向第一次上手这个仓库的人。目标是把兴业证券《基于高频时间维度的国债期货择时因子》
里的因子，在 75 个商品期货上做成**时序 CTA**（每个品种自己多空，等权组合），
并给出一个没有被样本外信息污染的绩效结论。

设计依据见 [Design.md](Design.md)，本文只讲怎么做。
文档里提到"第 N 节"时，指的都是那份设计文档。

## 一、规矩与环境

### 0. 三条不能破的规矩

这三条是整个实验可信度的全部来源。破了任何一条，后面所有数字都失去意义，
而且**不会有任何报错**——这才是危险的地方。

**规矩一：2022-01-01 起的数据，本阶段一次都不看。**
不读、不画、不统计、不"就瞄一眼"。`step1_shard_minutes.py` 把它们写进
`data/minute_shards/holdout_locked/` 之后即锁定，那是全仓库唯一允许写该目录的地方。
代码层面有三道闸：`config.assert_research_only(path)` 拒绝任何指向该目录的读取，
`config.assert_no_holdout_dates(index)` 拒绝越界的时间索引，
`shard_io.load_shard` 是唯一的分片读取入口且两者都调。
`step1_shard_minutes.py` 的"守卫"项会主动去撞这道闸，撞不动才算通过。

**规矩二：因子方向是先验，不许事后按数据翻转。**
`config.FACTOR_SIGNS` 里每个符号都来自论文原文或上一轮小时频的实测，
注释里写了出处。第 4 步发现某个因子的 IC 符号与先验相反时，脚本返回 1 并停下——
正确的反应是**回去查实现**，不是把符号改过来。改了就等于用样本内信息定向，
全部 t 值作废。没有先验的因子登记在 `NO_PRIOR_FACTORS` 里，只做对照组，不进主结论。

**规矩三：选参只在第 5 步做一次，用中心点而不是最优点。**
第 5 步扫完整个参数网格后，立刻用"距离参数云中心最近"挑唯一一组，
第 6 步不再碰参数。挑 `argmax(收益风险比)` 是过拟合，第 5 步会把它一并打印出来
作对照，但不采用。

## 二、因子与时间轴

### 2. 因子到底在算什么

一页版。细节在设计文档第 6-7 节。

#### 2.1 持续期族

核心量是**持续期**：第 i 根分钟 bar 的持续期 = `i − j`，其中 j 是**当日**、
i 之前、**最近**一根满足 `|Value_i − Value_j| ≥ Threshold` 的 bar。

一直找不到这样的 j，持续期就**从当日开盘累积**（0 基下标下 `dur = i`）。
这一条很容易写错成 0 或 NaN——写错了就等于把"整个上午价格没动过"
这种最有信息量的情形抹掉。

`Threshold` 是**动态**的：过去 N 个交易日**全部**日内一阶绝对差分池化后的第 M 分位数，
**不含当日**（含了就是前视）。N ∈ {200, 250, 300}，M ∈ {50, 52.5, 55, 57.5, 60}，
共 15 个组合。价格与成交量各算一套阈值，互不相干。

由持续期派生的因子：

| 因子 | 含义 | 方向 |
|---|---|---|
| `dfp_max` / `dfp_top3` | 持续期最长的 1 / 3 根 bar 的价格（公允均衡价格 FP）相对收盘价的偏离 | +1 |
| `pmt` | 价格稳态时点（持续期最长那根 bar 的日内相对位置） | −1 |
| `vr` / `vr_night` | 午前 vs 午后（夜盘 vs 日盘）的量能持续期比 | +1 |
| `vmt` | 量能稳态时点 | −1 |
| `dur_*` / `vdur_*` | 持续期的均值/标准差/最大值/极差/极端占比 | 无先验，对照组 |

DFP 必须除以收盘价归一化，否则铜和玻璃差几个数量级，等权组合会被高价品种主导。

#### 2.2 时间戳族

日内极值出现的**时刻**本身就是因子，且**完全不依赖 (N, M)**，所以单独存一份：
`ts_high`、`ts_low`、`ts_vmax`、`ts_tomax`，加上分时段版本
（`_am` / `_pm` / `_night`）与 `cnt_high_am/pm`、`is_high_am`、
`night_vol_share`、`night_day_range`。

时刻一律归一化为 `gamma_norm = (γ − 1) / (N_t − 1) ∈ [0, 1]`，
因为商品每天的 bar 数不一样（无夜盘 225、到 23:00 是 345、到 01:00 是 465、
到 02:30 是 555）。不归一化就没法跨品种等权。

#### 2.3 商品相对论文的三处扩展

1. **夜盘**。论文的国债只有"午前/午后"，商品要扩成"夜盘/午前/午后"三段。
   `trading_date` 是唯一合法的"日"定义：21:00 的夜盘 bar 属于**次一**交易日。
2. **无夜盘品种**（如 JD）的夜盘类因子必须是 **NaN，绝不是 0**。
   `config.NIGHT_DEPENDENT_FACTORS` 登记了全部 5 个这类因子。
   上一轮小时频就是被结构性零值把一个 t=3.05 的真因子压成了 t=1.1。
3. **时序而非截面**。论文做单标的择时，这里 75 个品种各自出多空信号，再等权合成。

### 3. 时间轴

| 区间 | 用途 | 允许做什么 |
|---|---|---|
| 2010-01 .. 2014-12 | 向后时间外检验 | **只看 IC 符号**，不得选参、不得据此调整任何设定 |
| 2014-07 .. 2015-12 | 预热 | 阈值（N 最长 300 日）+ 信号分位轨（W 最长 60 日）双层滚动的启动期，不计绩效 |
| 2016-01 .. 2021-12 | 研究期 | 全部可用。6 折 walk-forward：训练 3 年 / 测试 1 年 / 步进 1 年，测试年 2016…2021 |
| 2022-01 起 | 样本外 | **锁定**。本阶段完全不碰 |

2016 和 2017 这两折的训练窗口落在 2013-2015，那时夜盘尚未全面铺开，
`config.WF_FOLDS_WITH_SPARSE_NIGHT` 记着这件事，最终报告里必须标注。

收益口径（第 8.3 节）：`day_ret[t] = (openw[t+1] − openw[t]) / open[t]`，
即**今天收盘出信号、明天开盘进、后天开盘出**。链条是
`forward_return = day_ret.shift(-1)`、`execute_position = signal.shift(1)`，
两处滞后都不许省。

### 5. 逐步操作

以下把工作目录设为仓库根 `D:\liushengqi\time_factor_cta`，并且已经
`conda activate factor-mining`。

#### 第 1 步　切分片并验收

```bash
python scripts/step1_shard_minutes.py
```

默认切 75 个商品品种（`--all` 会连 8 个金融期货一起切，本实验不需要）。
先用 `--dry-run` 空跑一遍确认面板结构和品种齐全，再正式跑。

做了四件事：按品种取出 `FACTOR_FIELDS + PRICE_FIELDS` 八列、
把 `trading_date` 规范化、丢掉全字段皆空的行（未上市期）、
按 `HOLDOUT_START` 切成两份分别落盘。顺带从 `dominant_id` 的跳变提取换月日
写进 `data/roll_dates/{品种}.csv`，提完就把这个 object 列丢掉（省内存的关键）。

**这是全仓库唯一允许写 `holdout_locked/` 的地方。写完就当它不存在。**

注意两条警告：某品种缺 `open`/`openw` 时仍然会落盘（因子能算），
但第 8.3 节的 `day_ret` 算不出来，脚本末尾会把这些品种列出来；
分片一旦落盘就补不回这两列，所以发现了要在这一步解决。

落盘结束后会立刻跑验收：时间边界、夜盘归属不过就停；bar 数、换月日、清单有问题也停。dry-run 不验收。全量分片时验收全部品种。

#### 第 2 步　品种池

```bash
python scripts/step2_universe.py
```

逐年筛：日均成交额 ≥ 30 亿、当年 `closew` 非空的交易日占比 ≥ 90%、
有效交易日 ≥ 200。金融期货在 `config` 层面就已剔除。

关键是**时点有效**：第 y 年的池子只用 `[y − 1, y − 1]` 的统计量判定，
绝不用当年或以后的数据。回看窗口取 1 年而不是 3 年是刻意的——
ZC（动力煤）这类僵尸品种的成交额是断崖式塌缩，回看越长，塌缩之后还被留在池里的
年数越多。代价是新上市品种要晚一年进池，这个方向的保守可以接受。

产物除了 `universe_by_year.json`，还有 `turnover_trajectory.csv`（逐年成交额轨迹）
和 `entries_exits.csv`（进出池记录）。**跑完看一眼 `entries_exits.csv`**：
如果某年进出池品种数暴增，通常是成交额单位或字段出了问题，不是市场变了。

`universe_fixed.txt` 是研究期最后一年（2021）的池子，只给冒烟测试用，
**不要拿它跑主结论**——用研究期末的池子回测全研究期就是前视。主结论一律用逐年池。

#### 第 3 步　持续期抽查并计算因子

```bash
python scripts/step3_build_factors.py
```

先对 RB、CU、M 做持续期形态抽查，不过就停止，不会进入因子计算。

这一步不产生因子，只回答"持续期算出来的东西像不像持续期"。
默认抽查 3 个品种（RB、CU、M）× 2 列（`closew`、`volume`）× 3 个年份
（2016、2018、2021），用 N=250、M=55。要扩大范围就传
`--symbols` / `--years` / `--cols`。

验收标准只有一条：**`p95 / p50 ≥ 3`** 且非全 NaN。
持续期的分布本来就是右偏的长尾——大部分 bar 一两分钟就突破阈值，
少数几根能拖很久，而正是那几根携带信息。偏度塌了说明阈值算错了。

**刻意没有设"中位数持续期 ≥ 10 分钟"这类门槛**，原因见设计文档 §6.2.1：
商品价格是离散到 tick 的，当某品种"零变动分钟"的占比超过 M%，
第 M 分位数就直接落在 1 个 tick 上，阈值**退化**。
此时价格持续期的实际含义变成"距上次 tick 跳动几分钟"——
它仍然是一个有效的、甚至更干净的信息变量，但**经济解释变了**，
所以脚本会把"阈值退化样本占比"打印出来，超过一半时额外提醒。
这件事必须写进最终报告，也意味着对 M 的敏感性会集中在高分位一侧
（要到 60% 才开始脱离退化）。成交量持续期不受影响。

脚本内部有个容易做错且做错也不报错的地方：阈值要 N 个交易日预热，
所以每次都多读两年数据，**汇总时必须把预热年排除**（`keep` 掩码）。
混进去的话，预热年那些 NaN 会把缺失率稀释，看起来更干净，实则是错的。
`tests/test_step3_probe.py` 把这条钉住了。

#### 因子计算

```bash
python scripts/step3_build_factors.py
```

75 品种 × 15 个 (N, M) 组合 + 1 份时间戳族。落盘结构：

```
data/factor_daily/
  timestamp/{品种}.parquet        # 时间戳族，不依赖 (N, M)，只有一份
  N200_M50/{品种}.parquet         # 持续期族，每个组合一份
  N200_M52.5/...                  # 共 15 个目录
```

实现上做了三处优化，都不改变结果：每个品种的分钟数据**只读一次**，
日内坐标**只算一次**，15 个组合共用一个 `rolling_threshold_grid`
（3 个 N 各扫一遍即可覆盖 5 个 M，把 15 遍降到 3 遍）。
`tests/test_factor_cache.py` 证明网格结果与逐个调用逐元素相同。

**按 (组合, 品种) 粒度可续跑**：已存在的文件直接跳过，中断后重跑即可。
要强制重算加 `--overwrite`。只跑一部分用
`--combos N250_M55 --symbols RB CU`。

跑完自动做两项验收：

1. **因子健康度**（默认用中间组合 N250_M55，可用 `--health-combo` 改）：
   每个因子非空率 > 90%、不能全为同一个值、时点类因子必须落在 [0, 1]。
   夜盘类因子的缺失率**按有无夜盘分组统计**——不分组的话，
   一个完全正确的结果会因为混了无夜盘品种而被判不合格，
   进而诱导出 `fillna(0)` 这个致命修法。
2. **夜盘因子反向检查**：在无夜盘的 (品种, 交易日) 上，5 个
   `NIGHT_DEPENDENT_FACTORS` 必须**全是 NaN 且 0 值个数为 0**。
   出现任何非 NaN 值就返回 1，必须先修掉。

   这里的口径曾经错过一次，值得记住：**"有没有夜盘"不是品种属性，是挂牌历史事实**。
   2014 年之前整个市场都没有夜盘；C / CS / FU / L / PP / V 是 2019 年才有的；
   JD / AP 至今没有。所以判定必须逐 (品种, **交易日**) 做，
   按品种整体判会让 2019 年之前的那些年悄悄算出非 NaN 值。

两项都过才打印"可以进入第 4 步"。产物快照在 `runs/*_step3/`
（`factor_health.csv`、`build_log.csv`、`night_flags.csv`，以及
`night_by_year.csv`——逐 (品种, 年) 的有夜盘天数占比，用来核对上面那件事）。

#### 第 4 步　单因子 IC 与符号闸门

```bash
python scripts/step4_factor_ic.py
```

在 `N=250, M=55`（论文默认 N、M 区间中点）这**一组**参数上算时序 IC，
按 walk-forward 折分开，再给一行 `mean_of_folds`。
**这一步刻意不扫网格**——用 IC 挑参数就是选参，那是第 5 步扫描结束后的事，
放在这里等于提前偷看。

**一折 = 一段时间 × 一个品种池**，两者都要切。这里曾经只切品种池、时间传全历史，
于是"逐折 IC"其实是同一个全样本 IC 的六个品种池变体，折间一致性好得离谱，
第 7 步的"2010-2014 向后检验"还把研究期算了进去。时序 t 值的前提就是一折是一段时间。

##### 显著性用时序 t，不用横截面 t

表里有两列 t，别读错：

| 列 | 口径 | 回答的问题 |
|---|---|---|
| `t` | **时序**（主口径） | 这个因子在时间上稳不稳 |
| `t_cross` | 跨品种截面（仅留痕） | 这个因子在多少品种上同向 |

`t_cross` 不能当显著性用：它的分母是品种间 IC 的标准误，品种越同质分母越小。
商品同期高度相关（同一波宏观冲击推动整个板块），照这个口径"再加一个高度相关的
品种"就能把 t 抬上去，这显然不是显著性。

时序 t 的算法：**先在品种内按月算 Spearman IC，再在月内跨品种平均**，
一个月只贡献一个观测（`IC_PERIOD='ME'`，月内至少 `IC_PERIOD_MIN_OBS=10` 个观测，
至少 `IC_PERIOD_MIN_COUNT=6` 个月才给 t）。顺序反了就等于把约 40 个相关品种
当成独立样本。标准误用 **Newey-West**（Bartlett 权重，截断滞后
`floor(4·(n/100)^(2/9))`，落在 `nw_lag` 列），因为逐月 IC 是自相关的。

实测一句诚实的话：本数据上 `t_cross` 并没有虚高——强因子的时序 t 反而更大
（`ts_high` t=−9.59、`ts_low` t=+9.29、`dfp_top3` t=+8.40、`dfp_max` t=+8.27）。
换口径买到的是"t 回答了正确的问题"，不是"t 一律变小"。

##### 符号闸门

闸门只对 `PRIOR_FACTORS`（有先验的那些，对照组不参与）生效，三档：

- `ok`：方向与先验一致。
- `flip`：方向相反**且时序 t 显著**（`|t| ≥ SIGN_T_MIN = 2.0`）→ 返回 1，
  打印 `flipped` 并停下。**不要翻符号**，回去查实现。
- `flip_weak`：方向相反但**测不出来** → 只提示，不阻断。

分开这两档是必要的：`pmt` 实测 IC=+0.0008、t=0.22，六折里四折反向两折同向，
量级全在 0.016 以内。判成 `flip` 等于宣称"发现了方向错误"并把人送去查实现，
而真实结论是"论文的这个因子没迁移到商品上"。`vmt`（t=1.19）同类。
不给 t 值时退回严格口径，防止有人忘了传 t 而悄悄放松闸门。

`ic_by_fold.csv` 里 `mean_of_folds` 那一行的 `n_symbols` 是**有效折的品种数均值**，
折数另有 `n_folds` 一列（逐折行这一格为空）。折之间品种池会变，
所以不要把它当成累加值读。

#### 第 5 步　参数扫描与中心点选参

```bash
python scripts/step5_param_scan.py
```

每个因子把参数网格扫完，每组参数跑一次完整的单因子等权回测：

- 持续期族：N(3) × M(5) × W(9) × 分位轨(3) = **405 组**
- 时间戳族：不依赖 (N, M)，只给中间那一组，所以是 W(9) × 分位轨(3) = **27 组**

信号怎么出：因子先乘方向符号（统一成"越大越看多"），
再做滚动 MAD 标准化（1000 日中位数，除以 5×MAD，clip 到 [−1,1]），
然后在 `t−W .. t−1` 的滚动分位轨上比较——**窗口不含当日**，
上穿高轨 +1、下穿低轨 −1、其余 0。标准化窗口含当日是可以的
（当日因子值收盘时已知），分位轨不含当日是必须的。

绩效是 6 个测试年**拼接**后的扣成本收益。
每个因子一张完整的 CSV 落在 `data/research/scan/{因子}.csv`。
扫描写完后，立刻对目录里每一张表做中心点选参，写出 `selection.json`。

每个因子挑**唯一一组**参数：把年化收益和收益风险比
各自 **z-score 标准化（ddof=0）之后**再算欧氏距离，取离中心最近的一组。

先 z-score 这一步是**对论文的必要修正**，不是可选的实现细节：
年化收益的量纲是百分之几，收益风险比是零点几，
不标准化直接算距离的话，距离几乎完全由年化收益决定，
"中心点"就退化成"年化收益的中位数点"。这条修正写进了
`frozen_config.yaml` 的 `center_rule` 字段。

脚本同时打印 `argmax(收益风险比)` 作对照，并标注两者是否相同。
**对照就是对照，不采用。** 中心点与 argmax 差得远，说明参数云很散、
这个因子的稳健性可疑，值得在报告里说一句。

落盘前会走 `assert_research_selection`：递归遍历整个 selection 字典，
发现任何 2022 年及以后的年份或日期就抛 `FreezeError` 并拒绝写入。

##### 成本口径：手续费 + 滑点，都按换手计费

默认手续费 `0.00025`，滑点 **1 个最小变动价位**（`--slippage-ticks` 可改）。
滑点写成"穿越几个 tick"而不是一个固定比例数，因为固定比例在数学上等于把费率调大，
掩盖掉的恰好是最该看见的横截面结构：同样穿一个 tick，
铁矿（价位 ~640、tick 0.5）付 9.9bp，锡（~142000、tick 10）只付 0.7bp，
本样本 42 个品种实测相差 **13.7 倍**（中位 3.3bp）。等权组合的成本恰恰由
低价位品种主导，抹平它就是系统性低估。

tick 不查交易所表（会过时，而且对不上的时候不报错），由 `research/costs.py`
从分钟 `close` 的非零绝对一阶差分里估，逐 (品种, 年) 一个值，落在
`data/research/tick_size.csv`。要点两条：

- 取**出现得足够频繁的最小档**，不是众数。众数对活跃品种偏大一倍——
  焦炭 J 的 1.0 出现 20.5 万次而真 tick 0.5 只有 15.1 万次，取众数就把 J
  的成本翻倍（菜油 OI 同理，2 对 1）。只取最小差分也不行，那会捡到浮点噪声和
  个别异常跳动（PVC 的 1.0 只出现 1569 次，真 tick 是 5）。加频次下限再取最小，
  42 个品种里 41 个与挂牌规则完全一致，剩下 3 个偏差在 0.03% 以内。
- 逐年估是因为 tick 确实会改：本样本里 J/JM/I 在 2015 年 1→0.5、HC 2015 年 2→1、
  OI 2018 年 2→1、V/L 2021 年 5→1、AU 两次（0.01→0.05→0.02）。
  全样本估一个数，这些品种总有几年是错的。

**滑点必须在选参之前进来**：它按换手计费，会系统性惩罚高换手的参数。
`--slippage-ticks 0` 只是**对照档**，等于假装换手免费，不得用它选参或写结论。

想缩小范围调试：`--factors pmt dfp_max --windows 20 40 --bands 25:75`。
重估 tick 表加 `--rebuild-ticks`（要重扫一遍分钟数据，不便宜）。

#### 第 6 步　分族回测、费率与持仓对照

```bash
python scripts/step6_combo_backtest.py
```

成员参数全部来自第 5 步的 `selection.json`，本步**不再选参**。
默认跑四个族（`config.COMBO_GROUPS`）：

| 组合 | 成员 | 用途 |
|---|---|---|
| `COMBO_DUR` | dfp_max, dfp_top3, pmt, vr, vr_night, vmt | 持续期族主力 |
| `COMBO_TS` | ts_high, ts_low, ts_vmax, ts_tomax, night_vol_share, night_day_range | 时间戳族主力 |
| `COMBO_ALL` | 上面两组合并 | 全主力 |
| `COMBO_AGG` | dur_* / vdur_* 十个基础聚合 | **对照组** |

**分族而不是一锅端**，是为了能回答两个问题：论文的两个因子家族哪个在商品上更有效；
以及超额是不是只来自"持续期的均值和波动"这类平凡统计量——
如果 `COMBO_AGG` 跟 `COMBO_DUR` 打得一样好，那论文那套精巧定义就没带来增量。
`COMBO_AGG` 显著弱于前两组，才算复现成功。

组合内部是**等权**：`portfolio_return` 按年在池内品种上取等权平均，
NaN 不进分母（品种当年不在池里就不占权重）。
成本按 `|仓位变化| × (费率 + 滑点率)` 计，逐品种算，口径与第 5 步**必须同档**——
不同档的话第 5 步选出的参数和这里的绩效不在同一个货币单位上。
品种年末退池时，那笔平仓费收在**最后一个在池日**而不是第一个池外日——
收在池外日等于没收，因为等权平均只在当年池内品种上取。
`tests/test_research.py` 把这条钉住了。

组合还有一个副作用值得知道：等权平均多个成员信号会**显著降低换手**
（实测单因子约 195 次/年/品种，`COMBO_ALL` 降到 76 次），
因为成员之间不同时翻向，平均出来的仓位是小步移动而不是整数跳变。
在有滑点的口径下这不是细节，是组合能不能活下来的主要机制。

输出六项指标：年化收益、年化波动、收益风险比、Calmar、胜率、最大回撤。
除了拼接测试年的总表，每折还单独存一行 `y{年份}_*`，用来看跨年稳定性。

自定义组合：`--combo MY=pmt,ts_high,vr --combo OTHER=dfp_max`。

同一条命令接着做成本网格。同样的组合、同样的参数，只换成本：手续费 `0.00025 / 0.0005 / 0.001`
× 滑点 `0 / 1 / 2` 个 tick，共 9 格。输出里有一张
"行=手续费、列=滑点 tick 数"的收益风险比网格。

**为什么两维而不是把滑点折进费率**：折进去就再也分不开了，而两者的横截面形状
完全不同——手续费对所有品种是同一个比例数，滑点是 tick / 价位，品种间差 13.7 倍。
分开扫才看得出策略是被"所有品种一起变贵"打败的，还是被"低价位品种的滑点"打败的。
后者可以靠剔品种或压那部分换手应对，前者只能认。

滑点 0 那一列是**对照**，不是基准。写结论看 1 个 tick 那一列。

判读标准：**到 (0.001, 1 tick) 还站得住，结论才稳**。
在最便宜那一格好看、往右下走一格就塌掉，说明收益全被换手吃掉了，
那是一个交易成本假设的产物，不是一个因子。

然后对 `ts_high`、`ts_low`、`dfp_max`、`dfp_top3` 做持仓对照，不改 `selection.json`。
比较轨道中间空仓（flat，上面的原规则）和中间沿用上一笔方向（hold）。
每条同时给出零成本与默认手续费 + 1 个 tick，以及年均换手。
`IC4_cheap` 再去掉单 tick 成本高于 5bp 的品种。结果在 `hold_diag.csv`。

## 四、判读、禁区与排错

### 6. 怎么判断复现成功

按重要性排序，四条都要看。

**一、方向站得住。** 第 4 步有先验的因子折间平均 IC 符号与先验一致，
第 7 步在 2010-2014 上符号不翻。这是最低要求；这条不过，后面的绩效不必看。

**二、分族有差异。** `COMBO_DUR` 和 `COMBO_TS` 明显强于 `COMBO_AGG`。
三者打平意味着信息来自持续期的平凡统计量，论文那套定义没带来增量。

**三、扛得住费率。** 第 6 步的费率网格在 0.001 上仍有正的收益风险比。

**四、跨年不塌。** 第 6 步每折的 `y{年份}_ret_risk` 里，
不能是"某一年赚光全部、其余五年平的"。尤其留意 2016、2017 两折
（训练窗口的夜盘稀疏），这两年特别好或特别差都要在报告里解释。

指标本身的量级不设硬门槛。商品时序 CTA 在 0.00025 费率下，
拼接测试年的收益风险比落在 0.5-1.0 是合理区间；
超过 1.5 先别高兴，回去查有没有前视（最常见的两处：
分位轨忘了 `shift(1)`、以及 `execute_position` 少了一层滞后）。

### 10. 已知的口径局限

不是 bug，是做了取舍的地方。记在这里免得下次重新发现一遍，也免得误读数字。

- **第 4 步要看的 t 是时序 t，不是 `t_cross`**（见第 4 步小节）。
  `t_cross` 的分母是品种之间 IC 的标准误，把相关性很高的商品当成了独立样本，
  只能用来排序，不能当显著性。
- **某品种某天 `day_ret` 是 NaN 时，那天的手续费会跟着收益一起被剔除**。
  `symbol_net` 算的是 `仓位 × 收益 − 费率 × 换手`，收益缺失就整格 NaN，
  而 `portfolio_return` 不把 NaN 计入分母。只在品种上市初期和数据缺口日出现，
  方向是轻微低估成本。
- **滑点按 1 个 tick 计，不是冲击成本模型**。同样穿一个 tick，低价位品种付出的
  比例远高于高价位品种（本样本约 0.7–9.9bp，中位 3.3bp）。第 6 步把手续费和
  tick 数拆开扫，就是为了看见这件事。分位轨策略换手很高，1 个 tick 就足以把
  毛收益为正的因子做成扣费后为负。
