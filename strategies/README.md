# 策略

现在有两条策略，都已冻结，名单在 [`catalog.py`](catalog.py)。每条的 JSON 规格和代码在同目录，导入时互相核对，不一致就报错。两条只差熊市判断：一条慢，一条快。

| 策略 | ID | 目录 | 熊市窗口 | 冻结 |
|---|---|---|---|---|
| 按池宽1倍加慢趋势空头 | market_clock_slow_short | [`market_clock_slow_short/`](market_clock_slow_short/) | 60/120/250 | 2026-10-22 |
| 按池宽1倍加三窗口趋势空头 | market_clock_slow_short_fast3 | [`market_clock_slow_short_fast3/`](market_clock_slow_short_fast3/) | 20/60/120 | 2026-10-23 |

[`market_clock_carry/`](market_clock_carry/) 是两条共用的多头腿：五因子市场分数、展期收益、规格核对和 Book 基类。它自己不是策略。

## 多头腿（两条相同）

五个因子 `ts_low`、`ts_high`、`dfp_top3`、`ts_low_pm`、`ts_high_pm` 乘事前方向，各品种按自己过去 250 日（不含当天）做 z，截断 ±3，五个取平均，再在当年池内取平均，得到当天的市场分数。

收盘同时满足两件才做多：当天分数大于 0；该品种主力对次主力的年化展期收益，用前一个交易日的数，严格大于 0。近月高于远月时这个数为正。

## 空头腿（两条相同，只在熊市日开）

- 熊市：池内等权收盘到收盘日收益，按各窗口累计后取符号的平均小于 0。慢的那条用 60/120/250 日，快的那条用 20/60/120 日。窗口历史不足时不算熊市。
- 熊市日，品种自身 60、120、250 日收益符号的平均小于 0，并且滞后一日展期收益小于 0，权重 −1。
- 一个品种同一天只会在一条腿上：多头要展期 > 0，空头要展期 < 0。

## 成交、仓位和风控

两条腿都按当年池宽分 1 倍：每个入选品种拿 1 倍 × 权益 / 当年池宽。下一交易日第一根开盘成交：有夜盘时是夜盘开盘，没有夜盘时是日盘开盘。权重不变就留着，只成交手数差额。峰值回撤 10% 清仓，停 10 个交易日。展期收益池内某品种某年缺失超过 5% 就报错。

## 为什么两条都留

三窗口那条入熊、出熊都更快，2011–2021 的最大回撤更浅（−6.9% 对 −9.7%），只有 1 个亏损年；代价是来回切换更多，2016–2021 的 Sharpe 更低（1.29 对 1.37）。两条日收益相关 0.87。三窗口是看过 2011–2021 之后选的，登记时的比较门槛没过。打开 2025 时两条各自按门槛评估，不用 2025 挑哪条更好。

策略动机、研究期结果和信号层检验见 [`docs/guide.md`](../docs/guide.md)。

python -m backtest.engine 按池宽1倍加三窗口趋势空头 --research   # 只跑这一条

## 冻结

JSON 里 `status: frozen`、写了 `frozen_at`、`chosen` 等于 `parameters` 才算冻结。`--validation`、`--year`、`--oos` 先记台账再读；没冻结的策略在写台账之前就拒绝。冻结的 JSON 不改，规则变了就是新 ID 的新策略。不读 2026。
